========================================================
  뉴스 수집 방식 개선: AS-IS → TO-BE
========================================================

[ 개선 일자 ] 2025-02-14
[ 대상 파일 ] services/news_collector.py
[ 관련 파일 ] requirements.txt, config.py

--------------------------------------------------------
1. AS-IS (기존 방식)
--------------------------------------------------------

  흐름:
    고정 키워드 5개 → 네이버 검색 API → 기사 수집

  키워드:
    "정치", "국회", "대통령", "여당", "야당" (하드코딩)

  문제점:
    - 고정 키워드라 실시간 트렌드 반영 불가
    - 키워드 간 검색 결과 중복이 심함 (5회 호출해도 유사한 기사)
    - 특정 인물/사건 키워드가 없으면 관련 뉴스 누락
    - 정치 지형 변화 시 키워드 수동 수정 필요
    - 실질적으로 수집되는 유의미한 기사 수 적음

--------------------------------------------------------
2. TO-BE (개선 방식)
--------------------------------------------------------

  흐름:
    trendspyg로 실시간 트렌딩 키워드 수집 (Google Trends KR)
      → AI(Gemini)로 정치 관련 키워드 3개 필터링
      → 네이버 검색 API로 뉴스 수집
      → (트렌딩 키워드 없을 시 기존 고정 키워드 fallback)

  개선점:
    - 실시간 트렌딩 반영 → 지금 화제인 정치 이슈 포착
    - 키워드 간 중복 감소 → 3회 호출로 3개 뚜렷한 이슈 확보
    - AI 필터링으로 정치 카테고리 정확도 확보
    - 키워드 자동 갱신 → 유지보수 불필요
    - YouTube Shorts 조회수 증가 기대 (트렌딩 키워드 = 검색 유입)

--------------------------------------------------------
3. 비교표
--------------------------------------------------------

  항목              | AS-IS              | TO-BE
  ------------------|--------------------|--------------------------
  키워드 소스       | 하드코딩 5개       | Google Trends 실시간
  카테고리 분류     | 없음 (키워드 의존)  | AI 필터링 (정치 판별)
  API 호출 횟수     | 5회 (중복 많음)     | 3회 (각각 다른 이슈)
  시의성            | 낮음               | 높음 (실시간 트렌드)
  유지보수          | 키워드 수동 관리    | 자동
  Shorts 조회수     | 보통               | 트렌딩 일치로 상승 기대
  추가 비용         | 없음               | AI API 호출 (소량)
  추가 의존성       | 없음               | trendspyg, google-generativeai
  fallback          | -                  | 기존 고정 키워드 유지

--------------------------------------------------------
4. 기술 상세
--------------------------------------------------------

  신규 의존성:
    - trendspyg: Google Trends 한국 트렌딩 검색어 수집
    - google-generativeai: Gemini API로 정치 키워드 필터링

  동작 순서:
    1) trendspyg.download_google_trends_rss(geo="KR") → 트렌딩 키워드 ~10개
       - 트래픽(검색량) 정보 포함, 트래픽 높은 순으로 정렬
    2) Gemini API(gemini-2.5-flash-lite)에 키워드 목록 전달
       → 정치 관련 키워드 최대 3개 선별
    3) 정치 키워드가 3개 미만일 경우:
       → 부족한 슬롯을 트래픽 높은 핫 트렌딩 키워드로 자동 보충
       → 예: 정치 2개 + 핫 1개 = 3개 / 정치 0개 + 핫 3개 = 3개
    4) 선별된 키워드 3개로 네이버 검색 API 호출 (기존 로직 재사용)
    5) 트렌딩 수집 자체가 실패한 경우에만 기존 고정 키워드로 fallback

  키워드 선정 예시:
    케이스 1) 정치 트렌딩 풍부
      트렌딩: [윤석열(5000+), 탄핵(3000+), BTS(2000+), ...]
      → 정치 3개: [윤석열, 탄핵, 국회]

    케이스 2) 정치 트렌딩 부족
      트렌딩: [안젤리나 다닐로바(1000+), 단종(500+), 구잘(500+), ...]
      → 정치 0개 + 핫 3개: [안젤리나 다닐로바, 단종, 구잘]

    케이스 3) 트렌딩 수집 실패
      → fallback: [정치, 국회, 대통령, 여당, 야당]

--------------------------------------------------------
5. 로깅 & 모니터링
--------------------------------------------------------

  서버 로그 (Flask 콘솔):
    - [트렌딩] 10개 수집: [키워드(트래픽), ...]
    - [Gemini] 정치 키워드 선별: [키워드1, 키워드2]
    - [키워드 보충] 정치 N개 + 핫 트렌딩 M개: [키워드, ...]
    - [Fallback] 트렌딩 키워드 수집 실패 → 기본 키워드 사용
    - 에러 발생 시 원인(Exception) 상세 로그

  UI 키워드 로그 (화제 목록 상단):
    - 수집된 트렌딩 키워드 전체 목록 표시
    - 최종 선별된 검색 키워드 3개 태그 표시 (파란색)
    - fallback인 경우 주황색 fallback 뱃지 표시
    - 트렌딩 수집 실패 시 "수집 실패" 표시

  Gemini API:
    - 모델: gemini-2.5-flash-lite (무료 1,000회/일, 15회/분)
    - 2.0-flash 대비 무료 한도 넉넉, 단순 분류에 충분한 성능
